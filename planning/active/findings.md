## Key spaces already agree — but by coincidence, not construction

Two independent slugifiers:

```r
# gq — R/gq_style.R:104
normalize_layer_name <- function(name) {
  key <- tolower(gsub("[^a-zA-Z0-9]+", "_", trimws(name)))
  sub("^_|_$", "", key)          # sub, not gsub — first boundary only
}
# rfp — data-raw/styles/export_template_styles.R:79
slugify <- function(x) {
  s <- gsub("[^a-z0-9]+", "_", tolower(x))
  s <- gsub("^_+|_+$", "", s)    # gsub — both boundaries
  s[!nzchar(s)] <- "layer"; s
}
```

Measured over all 53 real layer names: **0 disagreements**, including
`" Biogeoclimatic Ecosystem Classification"` (leading space) → both give
`biogeoclimatic_ecosystem_classification`. gq's `trimws()` absorbs the boundary
case that would otherwise separate `sub` from `gsub`.

They agree today. Nothing enforces that they keep agreeing — hence the Phase 3
guard rather than an assumption.

## `osm.trail.qml` — an unindexed leftover, and why we vendor through the index

`rfp/inst/extdata/styles/vector/osm.trail.qml` is tracked but has **no
`index.csv` row**, and its name is not slug-conforming (`osm.trail`, not
`osm_trail`).

History:

```
7caeeeb 2026-08-22  Add the OSM trail style, lifted from the Roads - DRA donor (#171)
46a475e 2026-08-22  Put the styled trail layer into both templates (#171)
```

It is the gq#41 trail style's *donor*, hand-added one day before rfp#174 gave the
store an index. Once spliced into the templates, the generator re-extracted it as
the indexed `trails.qml`. The two differ in bytes (`4e41ef19…` vs `83e65f11…`) —
expected, since the indexed one came back through a template round-trip.

rfp's store guard asserts "every index row resolves to a file". It never walks
file → index, so an extra file is invisible to it. This is the incomplete-drift-
guard pattern from `code-check.md` ("A drift guard must cover every input it
claims to").

**Consequence for this work:** vendoring by `fs::dir_ls()` would silently pull
`osm.trail.qml` into gq and hand it a key of `osm_trail` that resolves to
nothing. Enumerate from `index.csv`, and assert *both* directions in gq.

## Layout: shared + override, not per-template

#39 proposes `inst/styles/<template>/<layer_key>.qml`. That writes 50 shared
files twice. rfp#174 measured that of 54 shared layers, exactly **3** differ in
symbology once labels/customproperties/cached-extents are canonicalized away —
and those 3 are already `vector/overrides/bcfishpass_mobile/`. Mirror that.

## Why gq does not need the lift

`rfp_qgs_style_export()`'s `<maplayer>` → `.qml` boundary is **positional, not a
filter**: `which(!tags %in% src)[1]`, copying to the end. Because
`expressionfields` appears in both the source and style blocks, a filter would
drop the style copy too. The consequence is that the source-tag list must be
*complete*, not merely correct — one missing tag and every later source tag leaks
into the QML. That was rfp#130, and it is now pinned by a QGIS-container oracle
(`rfp/inst/testdata/nodes/`).

Mirroring that rule in gq would be the cross-function-consistency trap at its
worst. gq vendors the committed artifact instead — the same dev-only, env-
overridable reach into rfp that `data-raw/reg_extract_themes.R` already makes.

## Dependency direction

rfp `Suggests: gq` + `Remotes: NewGraphEnvironment/gq` today, calling
`gq::gq_reg_main()` and `gq::gq_template_layers()`. gq must not add rfp to
Imports; the `data-raw` reach stays undeclared-by-design, as both existing
extract scripts document.
